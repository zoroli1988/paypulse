# 牛马薪动了！（paypulse）

桌面实时薪资悬浮窗。一个无边框、置顶、可点击穿透的小窗，把「今天已经赚到多少钱」按秒往前推。

> 月薪 8000 ÷ 21.75 计薪日 ÷ 7.5 小时 → 每秒钟 **0.0136 元**。
> 数字不是估的，是算的；而且每一帧都是从当前时刻重算的，不是累加的。

---

## 一、这个仓库里有什么

```
app/                       外壳（本仓，AGPL-3.0）
  src-tauri/src/
    lib.rs                 窗口、命令、快照、计时循环（外壳的心脏）
    settings.rs            Settings 树 + 补丁合并 + 校验 + 原子写
    settings_win.rs        设置窗口的视图模型：日历格子、年终奖摊分都在这儿算
    tray.rs                托盘菜单
    platform.rs            开机自启（注册表）、空闲检测、全局快捷键、边缘吸附
    toast.rs               自绘通知窗口（下班 / 午休 / 久坐）
  src-tauri/icons/tray.png 托盘图标（16px 专用剪影，见第六节）
  ui/
    index.html / hud.css / hud.js              悬浮窗
    settings.html / settings.css / settings.js 设置窗口（七组）
    toast.html / toast.css / toast.js          通知弹窗
    extra.html                                 记一笔（无独立 css/js，一页装完）
  tools/genv/              构建环境补丁（见第三节），不进安装包
  tools/as-shim/           生成上面那些补丁的源码
  tools/make-icons/        托盘图标的生成脚本
  tools/ui-probe/          状态截图 + 真窗口截图 + 设置页截图
paypulse-core/             计薪引擎（私有仓，此处以 path 依赖占位）
paypulse-clock/            时刻 → 已计薪秒的换算，带完整单测
paypulse-prototype.html    高保真原型（设计稿，唯一视觉基准）
```

**为什么分三个 crate**：外壳开源、引擎闭源。分界线的意义是「21.75 从哪来」这个问题在外壳里翻不到答案。`paypulse-clock` 单独拆出来，是因为它最容易算错、错了还看不出来（合盖、跨零点、午休边界），所以它必须有测试。

## 二、计薪规则（全部在引擎里，外壳不持有任何费率）

| 项 | 值 | 说明 |
|---|---|---|
| 计薪日 | 21.75 天/月 | 人社部口径：(365 − 104 双休) ÷ 12 |
| 每日工时 | 7.5 小时 = 27,000 秒 | 09:00–18:00 扣 90 分钟午休 |
| 日薪 | 367.816 元 | 8000 ÷ 21.75 |
| 时薪 | 49.04 元 | 日薪 ÷ 7.5 |
| 加班倍率 | **只有 1 档：1.5×** | 不区分休息日 / 法定节假日，理由见原型 02-A′ |

三条硬规矩：

1. **金额是 `f(now)` 的纯函数**，每帧重算、绝不累加。合盖 8 小时再唤醒，只会加 8 秒，不会加 8 小时。
2. **整数「毫」存储**（1 元 = 1000 毫），全程 `i64`，只在渲染那一行除以 1000。前端拿到的永远是毫。
3. **双账物理隔离**：`paid` 进月薪，`shadow`（白干价值）**只写不读**，永远不加进主账。

另外两条容易被忽略但必须有的：

- **不上班的日子自动暂停**：模型认识「今天是什么日子」——`Calendar::is_workday()` 按「补班 > 放假 > 周模板」判定，所以法定假日、调休、单休、大小周都算得对。不工作的那天直接返回 `(0, true)`，不给数字。否则打开一次就虚增 367.82 元。
- **午休只扣走过的那一段**：12:00 之前不扣，13:30 之后扣满 90 分钟，中间按实际走过的时间扣。

界面有七个状态。它们**都是算出来的，不是点出来的**——时钟给时段，用户只声明「我在加班」和「今天请假」：

| 状态 | 何时 | 主色 | 右槽 | 底部按钮 |
|---|---|---|---|---|
| 在岗 | 上班时间内 | 绿 | 距下班 | 无 |
| 午休中 | 12:00–13:30 | 琥珀 | 午休剩余 | 我在加班 |
| 已下班 | 工时满了、没声明加班 | 灰 | 已过 | 我在加班 |
| 加班中 | 声明了加班 + 设置「按 1.5× 计薪」 | 蓝 | 已加班 | 结束加班 |
| 义务加班 | 声明了加班 + 设置「不计加班费」，或午休加班 | 琥珀（**主数字仍是绿的**） | 已白干 | 结束加班 |
| 请假 | 今天在 `leave_days` 里 | 紫 | 余额 N 天 | 无 |
| 休息日 | 非工作日（法定假日 / 调休上班之外没排班的日子，且没标请假） | — | 整块遮罩，一个数字都不给 | 无 |

**「加班怎么算」是设置，不是按钮。** 这是照原型稿的设置页做的：那里只有一个下拉（「不计加班费（仅记白干价值）」），所以悬浮窗上只留一个「我在加班」。早先做过「我在加班 / 不计加班费」两个按钮，那是错的——等于让人每加一次班选一次费率。

四个状态的细节都不能省：

- `已下班`：少了它，晚上七点还挂着一个「距下班 00:00:00」，看着像卡死。
- `午休中`：这一档的右槽是「午休剩余」，而且金额必须冻住（午休不计薪）。用「距下班」会让人以为下午的工时被吃掉了。
- `义务加班`：主数字保持绿色——钱确实到账了，不该因为这段没加班费就整块变色；只有状态和代价转琥珀。
- `请假`：三列指标整组换掉（类型 / 剩余 / 本月），因为那天没有「每秒进账」可言；进度锁 0%，按钮不出现。

叠加在状态之上的还有两个开关（托盘里的）：`暂停计时` 把所有主色压成灰（绿色在这一层的语义是「正在进账」，暂停还用绿会让人以为数字在动）；`隐藏金额` 只糊数字、保留进度条。

## 三、构建（Windows）

对普通开发机来说这就是一句 `cargo build`。但**在只用 rustup 的机器上会连着踩三个坑**，这里记录解法，省下你半天。

### 3.1 前置

```bash
rustup target add x86_64-pc-windows-gnu
# 或直接用默认 gnu 工具链；项目 .cargo/config.toml 已指定 rust-lld + self-contained
```

Tauri 还需要 WebView2 运行时（Win10 1803+ / Win11 自带）和 `@tauri-apps/cli`：

```bash
cd app && npm install
```

### 3.2 四个坑与解法

rustup 现在的 `x86_64-pc-windows-gnu` 工具链，`lib/rustlib/<target>/bin/` 里只有 `rust-lld` 和一堆 `llvm-*`，**既没有 `as`、`windres`，也没有 `dlltool`**（早年的 `rust-mingw` 组件还给 `dlltool` 和 `ld`，现在不给了）。于是构建时会依次报：

| 报错 | 缺什么 | 解法 |
|---|---|---|
| `error calling dlltool 'dlltool.exe': program not found` | `dlltool` | 从 msys2 的 `mingw-w64-x86_64-binutils` 里取 `dlltool.exe` |
| `dlltool.exe: program not found`（同一句、另一个位置） | `as` | 同一个包里取 `as.exe` |
| `tauri-winres: NotAttempted("windres")` | `windres` | 同一个包里取 `windres.exe` + `windmc.exe` |
| `windres: preprocessing failed` | `gcc -E` | 用 `app/tools/as-shim` 里的 `gcc` 替身 |
| `too many exported symbols (got 91856, max 65535)` | — | 把 `[lib] crate-type` 改成只有 `rlib` |
| `cargo test` 启动即挂 `0xc0000139` | comctl32 v6 清单 | 已由 `build.rs` 处理，见 3.5 |

把四个 exe 放到**同一个目录**（`app/tools/genv/bin/`），然后把这个目录加到 `PATH` 最前面：

```bash
export PATH="$PWD/app/tools/genv/bin:$PATH"
```

`dlltool` 会在自己同目录 / `PATH` 里找 `as`，所以放一起最省事。

**`dlltool` 那条最容易被漏掉**，因为 `cargo check` 一路绿灯（check 不链接），`cargo test` 也过——它只在真要产出可执行文件时才咬人。触发点在编译 `parking_lot_core`：它声明了 `#[link(name = "ntdll")]`，rustc 得为这个系统 DLL 现场生成一个 import library，于是去调 `dlltool`。所以 `tauri build` 是第一次真正撞上它的地方，报错信息却指向一个跟 tauri 毫无关系的 crate。

四个工具同版本最稳（`as` 2.44 配 `dlltool` 2.44）。取法：

```bash
V=mingw-w64-x86_64-binutils-2.44-4-any.pkg.tar.zst
curl -sL -o /tmp/bu.zst "https://mirror.msys2.org/mingw/mingw64/$V"
"C:/Windows/System32/tar.exe" -xf /tmp/bu.zst -C /tmp/bu    # bsdtar 自带 zstd
cp /tmp/bu/mingw64/bin/{as,dlltool,windres,windmc}.exe app/tools/genv/bin/
```

（用 Windows 自带的 `bsdtar` 解 `.tar.zst`，不需要另装 zstd。）

### 3.3 那个 `gcc` 替身是什么

它只实现一件事：`gcc -E 输入 -o 输出` 或 `gcc -E 输入 > 输出` 时把输入原样吐出来。

为什么这样是**正确**的：`tauri-winres` 生成的 `resource.rc` 里没有 `#include`、没有宏，只有 `VERSIONINFO`、`ICON` 和一段 manifest 字符串。对这种文件，「输入 = 输出」就是预处理器的正确输出。

重新编译替身：

```bash
cd app/tools/as-shim && cargo build --bin gcc
cp target/x86_64-pc-windows-gnu/debug/gcc.exe ../genv/bin/gcc.exe
```

> 这些替身是**构建环境补丁，不是产品代码**，永远不进安装包。
> 用 MSVC 工具链（`llvm-rc` / `rc.exe`）的机器完全不需要它们。

### 3.4 跑起来

```bash
cd app
npm run dev          # = tauri dev，会一起编译 ui 与 src-tauri
```

只想看 Rust 侧是否通过：

```bash
cd app/src-tauri
cargo check -j 1     # 首次必须 -j 1，见下
cargo test -j 1      # 外壳 87 + 时钟 33 + 引擎 10 = 130 个
```

**`-j 1` 不是洁癖**：并行编 `windows 0.62` / `indexmap` / `http` / `cfb` 时，rustc 会崩在 `STATUS_STACK_BUFFER_OVERRUN (0xc0000409)`。单线程编就没事。依赖编过一次之后，后续增量构建不用再带。

> 前端资源是**编进二进制**的（`frontendDist`）。改了 `ui/` 下的文件必须重新 `cargo build`，只重启程序不会生效。

### 3.5 `cargo test` 报 `0xc0000139` 是怎么回事

症状：测试 exe 一启动就被加载器打死，一个测试函数都执行不到。

```
process didn't exit successfully: ... (exit code: 0xc0000139, STATUS_ENTRYPOINT_NOT_FOUND)
```

原因是 `tao` / `muda` 这些窗口库会导入 `comctl32.dll` 的 `SetWindowSubclass`、`TaskDialogIndirect`、`RemoveWindowSubclass`、`DefSubclassProc`。这几个函数**只存在于 comctl32 v6**，而 v6 只有在程序嵌了 `Microsoft.Windows.Common-Controls 6.0.0.0` 清单时才被激活；缺清单就加载 5.82，缺导出，于是加载器直接失败。

`tauri_build::build()` 只给 **bin** 嵌清单，不给 **test** 嵌。所以 `build.rs` 里补了一步：用 `windres` 把同一份清单编成 COFF 对象，再通过 `cargo:rustc-link-arg` 塞给所有可链接目标。

两个坑都记在这里，省得下次再踩：

- 不能用 `cargo:rustc-link-arg-tests` —— 它只作用于 `tests/` 目录下的集成测试，对 lib 自带的单元测试 harness 会直接报 `does not have a test target`。
- 资源 id 必须是 `1`（加载器只认 `CREATEPROCESS_MANIFEST_RESOURCE_ID`），而 bin 已经有 id 1 / lang 1033 的那份，所以测试这份标成**语言中立**（`--lang 0`），否则 lld 报 `duplicate resource: type MANIFEST (ID 24)/name ID 1`。

清单内容刻意与 tauri 生成的那份**完全一致**：两份同时链进 bin 时，无论加载器挑哪一份，行为都没差别。（DPI 感知不在清单里，是 Tauri 运行时调 `SetProcessDpiAwarenessContext`。）

### 3.6 出安装包

```bash
cd app
npm install          # 只装 @tauri-apps/cli，这是个零运行依赖的项目
npm run build        # = tauri build，产 NSIS 安装包
npm run build:no-bundle   # 只出 exe，不打包（本地自测用，快得多）
```

首次 `build` 会联网下载两样东西：`@tauri-apps/cli` 和 NSIS 本体（落在 Tauri 自己的缓存目录，不在仓里）。离线机器请用 `build:no-bundle` 出裸 exe。

产物在 `src-tauri/target/x86_64-pc-windows-gnu/release/bundle/nsis/`。

**只打 NSIS，不打 MSI**：`bundle.targets` 写死成 `["nsis"]`。MSI 要走 WiX，那是另一套下载和另一套签名要求，而这个工具没有任何需要 MSI 的部署场景（无组策略分发、无域环境）。

**安装模式是 `currentUser`，不是 `perMachine`**，理由三条：

1. 自启写的是 `HKCU\...\Run`——那是「当前用户登录时启动」。装到 `Program Files` 而自启只对一个人生效，等于两套作用域错配：机器上另一个账户能看到它装着，但永远不会自启。
2. 装 `Program Files` 每次升级都要过一次 UAC。一个常驻托盘的小工具，每次更新弹一次蓝色确认框，用户第三次就会去搜「怎么卸载」。
3. 它装到 `%LOCALAPPDATA%\paypulse`，卸载不留管理员痕迹，也不需要管理员权限就能装。代价是同一台机器的其他 Windows 账户看不到它——对「我看着自己的工资」这个语义，这是对的。

这三个字段（`targets` / `installMode` / `icon`）是打包唯一需要人工判断的地方，其余都是默认值。改 `installMode` 请连带回看自启那条：注册表里存的是 `std::env::current_exe()` 当场读出来的绝对路径（`setup()` 里每次启动都重新对齐一次，就是因为换安装目录后那条旧路径会让下次开机启不起来——而用户不会知道为什么）。换安装位置这件事它自己扛得住，换**用户作用域**扛不住：老版本写在别人 `HKCU` 下的那条会被留在原地。

#### 装一次，验一遍

配置对不对，静态看不出来。`app/tools/verify-install/verify-install.ps1` 走完 装前 → 安装 → 装后 → 卸载 → 卸后 五步，每步抓一次系统状态（注册表、目录、快捷方式）再逐项核对：

```powershell
powershell -ExecutionPolicy Bypass -File app\tools\verify-install\verify-install.ps1
powershell -ExecutionPolicy Bypass -File app\tools\verify-install\verify-install.ps1 -Keep   # 查完不卸
```

它核对的九项里，有四项是静态检查看不出来的：卸载串是否指向真实存在的文件（指向错的表现为「点了卸载什么都没发生」）、「应用和功能」里的发布者是否为空、开始菜单快捷方式、从**安装路径**启动能否跑起来（自启注册表写的就是这个路径，这条过了等于自启路径也对）。

脚本必须带 BOM 存盘：Windows PowerShell 5.1 按系统 ANSI 读无 BOM 的 `.ps1`，中文会碎成乱码、字符串未终止，报一堆毫无关系的语法错。`-ExecutionPolicy Bypass` 只作用于这一次进程，不写注册表。

#### 卸载时数据留不留

卸载向导有一个「删除应用程序数据」勾选框，**默认不勾**。勾了才会删 `%APPDATA%\com.bydota.paypulse`（含 `settings.json`，也就是你填的月薪和排班）与 `%LOCALAPPDATA%\com.bydota.paypulse`（WebView2 缓存，实测 67.9 MiB / 310 个文件）。

这个默认是刻意的，别把它当 bug 改掉：静默卸载（`/S`）**不会**勾它，所以 `-Keep` 之外跑一遍 `/S` 卸载后，那两个目录还在。一个算工资的工具，卸载时顺手删掉用户填的数字，比留 68 MiB 垃圾严重得多。反过来说，勾了就是真删——重装也不会回来的那种。

WebView2 的缓存目录按 identifier（`com.bydota.paypulse`）命名，安装目录按 productName（`paypulse`）命名，两者不是一个地方。看到 `%LOCALAPPDATA%` 下同时有 `paypulse` 和 `com.bydota.paypulse` 不必奇怪。

## 四、前端约定

`ui/hud.js` 里**一行金额算术都没有**。它只有格式化函数：

- `money3(milli)` —— 毫 → `288.968`（**三位小数**，第三位每秒跳十几次，就是这个产品的全部意义）
- `money2(milli)` —— 毫 → `2,574.71`（本月底栏用千分位）
- `hms(sec)` —— 秒 → `01:36:28`

金额、进度、剩余秒数、白干、月度合计全部来自 Rust 的 `tick` 返回值。想验证这条纪律：把 `hud.js` 整个删掉重写一个，数字不该有任何变化。

前端只拥有两样东西：**文案**（`LABELS` 和 `tipOf()` 里那张表，逐句抄自原型稿）和**格式**。阈值（`shadow_sec < 600` 之类）留在前端是因为它决定「显示哪句话」，不决定「算多少钱」。

窗口高度跟着内容走（`resize_hud`）。**这不是审美问题**：窗口是透明的，超出内容的那部分仍然会吃掉鼠标点击——用户点桌面图标，点到的却是这块看不见的窗口。白干条一出现，窗口就会自己长高 37px。

宽度也一起报：三档的宽度写在 CSS 里（236 / 302 / 322），高度是内容撑的，只有前端量一次才知道。所以 `resize_hud(width, height)` 收两个数，从不让 Rust 猜宽度。

首帧画完之前窗口是隐藏的（配置里 `visible: false`）。不这样的话，开机时会先闪一块纯黑的圆角矩形——WebView2 起来要一秒多。

右上角那个 `◎` 是鼠标穿透开关，只在悬停时浮出来（原型稿里没有这个按钮，它是设置页的一项，所以不能占版面）。开启后点击直接落到下面的窗口，只能从托盘关掉——用 `set_ignore_cursor_events` 而不是隐藏窗口，隐藏会丢掉置顶层级。

拖动区用 `data-tauri-drag-region`。注意 Tauri 2 会把**双击**解释成「最大化」，在 `hud.js` 里用捕获阶段拦掉了——302px 的悬浮窗双击变全屏，很难解释。

### 怎么快速看一眼所有状态

`app/tools/ui-probe/shot.py` 把 `ui/` 里的真页面放进浏览器，用一份假后端喂数据，把九个状态各截一张：

```bash
python app/tools/ui-probe/shot.py                  # 十态（标准档）+ 八个尺寸组合
python app/tools/ui-probe/shot.py unpaid_break     # 只截一个
python app/tools/ui-probe/shot.py on@compact       # 指定尺寸档
# 结果在 app/tools/ui-probe/out/
```

为什么需要它：`午休 / 加班 / 白干 / 请假 / 暂停 / 隐藏金额 / 休息` 这些状态要么得等时间、要么得点按钮、要么得等到周末。远程桌面里点不了鼠标，也等不到周六。

它验的是**布局**：有没有溢出、文字有没有被挤、按钮该不该出现、午休时右槽是不是「午休剩余」、白干条出现后卡片有没有被撑高、紧凑态该消失的东西有没有真的消失。
它不验算数——那是 `cargo test` 的事。

四个坑已经写进脚本里了：宽度必须**按档**钉死（302 / 236 / 322，否则按浏览器视口排版，看起来像溢出；body 窄于 `.hud` 会把展开档右边切掉）、必须关掉 CSS 过渡（否则截到半截动画，像按钮坏了一半）、裁剪上限要留够（展开态 + 白干条 + 动作行是最高的一档，裁 400 会把进度条切掉）、`window_shot.py` 找窗口的宽度阈值不能太高（紧凑档 236 逻辑像素，125% 缩放下只有 295 物理像素，按 300 卡正好把它筛掉）。

想看**真窗口**而不是浏览器里的那份，用 `window_shot.py`（同样靠 `PrintWindow`，对透明窗口也有效）：

```bash
python app/tools/ui-probe/window_shot.py out.png        # 抓窗口
python app/tools/ui-probe/window_shot.py out.png click 100 178   # 先点窗口内坐标再抓
```

**如果抓到全黑，先别怀疑代码**：进程刚起来的那一两秒 WebView 还没画完。多抓两次，第二次起就正常。

设置窗口另有一个探针 `settings_shot.py`，七组各拍一张（980×720）：

```bash
python app/tools/ui-probe/settings_shot.py          # 七组
python app/tools/ui-probe/settings_shot.py pay look # 只拍这两组
# 结果：out/set-pay.png … out/set-about.png
```

它抓的是**真页面**（`settings.html` + 假后端 `settings-stub.js`），数字照抄原型：8000 / 21.75 天 / 7.5 h → 日薪 367.82、时薪 49.04、每秒 0.013623。截图能和原型逐项对上，才看得出是「照做」还是「大概是那个意思」。

两个坑：`--window-size` 必须显式给（默认视口只有 734×487，两栏会挤成一栏），以及裁剪**不能用超过原图的框**——PIL 会用黑边补齐，「视口没到位」就被伪装成「右边有一块黑」。

## 五、和原型稿的对照

`paypulse-prototype.html` 是唯一视觉基准。`ui/` 的结构、类名、文案、字号、字距、圆角、阴影、每个状态的配色都照它抄（`#hud` 那段，231–375 行）。下面是**刻意不一样**的地方，每一条都有理由：

| 差异 | 原型稿 | 实现 | 为什么 |
|---|---|---|---|
| 背景 | `rgba(17,19,24,.84)` + `backdrop-filter: blur(30px)` | `rgba(17,19,24,.92)`，无模糊 | WebView2 的透明窗口里没有「背后」可以模糊，`backdrop-filter` 的合成结果是**整块黑屏**（实测）。改成把模糊换成更实的底色：背后透出来的是压暗的桌面，不是模糊的桌面 |
| 已下班 / 加班的右槽 | 「距下班 00:00:00」 | 「已过 / 已加班 HH:MM:SS」 | 同一个数（超出下班点的秒数），换个说法。`00:00:00` 挂在那儿像卡死 |
| 鼠标穿透 | 设置页里的一项 | 悬停时浮出的小 `◎` | 功能要有，但不能占版面。静置时的像素与原型稿一致 |
| 义务加班时的「已工作」 | 冻结（演示里 `running = false`） | 继续按墙上时钟涨 | 你真在加班，工时就在涨；封顶的是钱，不是时间 |
| 本月已赚 / 还剩 | 示意值 `¥7,588.97` / `20` | 按真实工作日算：`已过完的工作日 × 日薪 + 今日已赚` | 原型稿那两个数对不上它自己写的 `MONTH_DONE_BEFORE = 6`（6 天应该是 2,495.86），是张占位图。实现按周一至周五真实计算，11 月正好 21 天，与稿子的口径一致 |
| 尺寸变体 | `size-compact` / `size-expanded` 两档 | 已做，三档循环（见第五节附录） | 紧凑 236 / 标准 302 / 展开 322，双击标题区、滚轮、托盘三处都能切 |
| 请假态 | `leave`（演示可切） | 已做：托盘「今天请假」/ 设置页开关 | 日期列表而不是布尔——只有存了日期，「本月 -1 天」和月合计的扣减才算得出来 |

其余一律照抄，包括这些容易被「优化」掉的东西：

- 金额 **43px / 字距 −2.4px / 三位小数**，`¥` 23px、透明度 .8
- 三列指标（每秒进账 / 时薪 / 日薪）**在所有状态下都不变**——原型稿的变体卡里它们会换成本班/白干/倍率，但那只在变体卡里，活窗口上不是
- tip 那一行 11px、斜体、`rgba(255,255,255,.32)`、`min-height: 16px`（不够高的话，文案换行会让窗口上下跳）
- 按钮 28px 高、9px 圆角，琥珀渐变只给「我在加班」，`结束加班` 永远是中性灰
- 白干条的琥珀渐变、`不计入月薪` 贴右侧、9.5px

### 三档尺寸

三档不是「缩放比例」，是**三套版式**：紧凑砍内容，展开加内容。所以它在配置里是枚举，不是 width 数值。

| 档 | 宽 | 高（实测） | 原型标注 | 差别 |
|---|---|---|---|---|
| 紧凑 | 236 | 111 | 118 | 砍掉指标行、本月、tip、白干条、动作行；金额 31px、`¥` 17px；右槽只留「已工作 + 百分比」 |
| 标准 | 302 | 242（带动作行 258） | 242 | 默认 |
| 展开 | 322 | 330（带动作行 339） | 330 | 多一块「奶茶等价物」；金额 39px |

三个入口都走同一个 `cycle_size(dir)`：**双击标题区**、**在窗口上滚轮**、**托盘菜单「切换尺寸」**。顺序是紧凑 → 标准 → 展开 → 紧凑。

几处必须这么做的细节：

- **宽度在切档那一刻就改掉**，不等前端下一帧。等的话中间有一帧「窗口比内容宽」，多出来的透明区域会吃掉桌面上的那一下点击。
- **高度永远量出来**，不钉死。原型标注的 118 / 330 是设计值，实际受字体度量影响（实测 111 / 339）——钉死就会在「白干条出现」时把内容裁掉，那是之前踩过的坑。
- **滚轮要节流**。一次滚轮会连发十几个 `wheel` 事件，不拦的话滚一下能从紧凑直接绕到展开还多转一圈。300ms 内的重复事件直接丢掉。
- **紧档不显示「我在加班」**。这不是漏做：原型稿原话是「紧凑态默认不显示动作行——那个尺寸只留数字，要操作就双击展开」。CSS 的权重还正好卡在这儿——`.hud.size-compact .hud-actions` 和 `.hud[data-act] .hud-actions` 都是 0,3,0，靠**后写者赢**，所以 `.size-*` 那组规则必须排在 `[data-act]` 之后，否则按钮会漏出来。
- **窗口变宽后要推回屏幕**（`clamp_into_screen`）。默认位置贴右上角，从 302 切到 322 会多出 20px 跑到屏幕外；不处理的话那 20px 里的内容用户永远看不到，下次启动还会按存下来的坐标摆回去。

展开态那块等价物全部在 Rust 里算：

```
杯数 = 已赚 / 单价        （放大十倍再四舍五入，保留一位小数）
两条小进度条 = 杯数 / 累计目标 1000、杯数 / 今日目标 12
```

单价 `¥25`、目标 `1000 杯`、今日目标 `12 杯` 都是配置项（原型 07 章的等价物组，现在在「设置 · 通知与文案」里能改）。这些东西看着像装饰，但**「折合几杯」也是除法**，一样受「外壳 JS 里一行算术都没有」这条约束管，所以它跟金额走同一条路。

「距下班还能买」在已下班 / 加班时是 `0.0 杯`——日薪已经封顶了，那时候显示「还能买 3 杯」是骗人的。

### 请假态

请不是「今天请假了没」一个布尔，而是一串**日期**（`leave_days: ["2026-11-10"]`）。原因很具体：只有当它知道「哪几天」，才算得出「本月 -1 天」和「本月已赚要少一天」；布尔到第二天就失效，用户会看到数字自己跳回去。

请假当天：

| 位置 | 显示 |
|---|---|
| 主数字 | `0.000`，紫色（`#A78BFA`） |
| 三列 | **类型 / 剩余 / 本月** —— 不是每秒 / 时薪 / 日薪 |
| 右槽 | `余额 4.5 天` |
| 进度 | `0%`，进度条空着 |
| 底部 | `不赚钱的日子，也是日子` |
| 动作行 | 不出现（原型 1551 行：在岗、请假都不显示按钮，避免误触） |

两处与直觉不同的地方：

- **请假压在休息日之前判**。你在周六点了「今天请假」，应该看到「请假」，而不是被「今天休息」的遮罩盖住、以为标记没生效。
- **月合计要扣掉请假天**。不扣的话「本月已赚」会凭空多出一天工资——这是这个产品最不能犯的错。只数工作日：手滑标了个周六不该扣两次（那天本来就不计薪）。

入口有两个：托盘「今天请假」勾选项，和设置页「薪资与口径 → 请假」里的开关。两者读写同一份状态。

**枚举落盘只有一套拼写**，这件事有测试钉着（`every_setting_survives_a_restart`、`the_font_choice_survives_a_restart`）。曾经 `num_font` 出现过两套：写出去是 `jetbrains`，读回来只认 `jb`，于是选过 JetBrains 或系统等宽的人一重启就被悄悄换回 SF Mono——界面上看不出来，直到再打开设置页发现高亮跑回第一张卡。所以这一项改成了手写 `Serialize`，输出就是 `sf` / `jb` / `sys`。

另外两个数据模型值得单独说：

- **暂停**和**午休加班**都是**区间**，金额/时长是区间的纯函数，不是计数器。暂停期间合盖 8 小时，醒来扣的就是真实的 8 小时，而不是「多跑了 8 万次 tick」。
- 午休加班那段要**收口**（记下 `end`）而不是删掉：原型稿的规矩是「当天有白干记录就保留」，结束加班不该让上午记的账凭空消失。收了口的段长度固定，没收回的那段才用 `now` 去量。

托盘菜单（右键图标）：

```
显示悬浮窗
切换尺寸            ← 紧凑 → 标准 → 展开，和双击标题区、滚轮同一个入口
─────
暂停计时
今天请假            ← 写进 leave_days，第二天自动失效
隐藏金额
鼠标穿透
─────
加班按 1.5× 计薪     ← 不勾 = 只记白干，这就是设置页「加班怎么算」那个下拉
─────
设置…
重置位置
─────
退出
```

「加班怎么算」在设置页和托盘各有一份，是**故意的**：一年改不了一次的东西放设置里，但临时改一下不该逼人开窗口。两处读写同一份配置，改完 `sync_checks` 会把勾选刷成一致。

左键单击托盘图标是「显示 / 隐藏」，不弹菜单——这是最高频的动作，不该多点一次。

托盘图标用 `icons/tray.png` 而不是主图标：托盘在 100% 缩放下只有 16×16，主图标那套「方块 + 鼻环 + 鼻孔」在这个尺寸会糊成一个点。生成脚本是 `tools/make-icons/gen_tray.py`（膨胀描边 + 超采样降采样）。

## 七、设置窗口

原型 04 章那七个分组，左边导航、右边真控件、没有「保存」。窗口是独立的一扇（980×720，无系统标题栏）。

### 哪个是真的，哪个还没接

这一栏比截图有用——它决定你点下去会不会有反应：

| 数据与隐私 | 存储位置（真实路径）、**清除数据**（今天 / 本月 / 全部，输 DELETE 放行） | — |
| 关于 | 版本、内核、许可、数据目录 | 检查更新（没有服务端，也就没有可信的清单） |

「待接入」的行**照原型的位置摆着，但控件是灰的、右边写着「待接入」**，并在说明里写清为什么不做。给一个点了没反应的开关，比不给更让人火大。

只剩两项没做，都是「做了会更差」或者「做了也是假的」：

- **「所有屏各显示一个」**。每扇窗口背后是一整个 WebView，两块屏就是两倍内存，而这个东西的定位是角落里一个小窗——主屏一个，够用了。
- **检查更新**。它要的不是一个 HTTP 请求，是一条**能推安装包的通道**：清单 + 签名 + 公钥得在二进制里，否则第一个劫持 DNS 的人就能给所有人装东西。没有服务端就没有可信清单，所以这一项连「检查」按钮都不给。真要做，顺序是：先定清单格式（版本 + 各平台包 url + sha256 + 签名段），再在构建里加一步「私钥签 manifest」，客户端用**内置公钥**验——公钥不能从网上下，那条通道本身就是被防御的对象。

三个刻意的取舍：

- **弹性排班做成了「整套作息平移」，不是「只挪起点」**。原型那张卡写的是「按首次活动滚动」；实现上把 10:30 定成上班点之后，午休也跟着从 13:30 开始。只挪起点不挪午休的话，10:30 上班的人在 12:00 就被判成午休，白干条会莫名出现在中午。另外它那张卡是**开关**而不是「第四种形态」——弹性跟哪几天上班无关，双休的人一样可以弹性。
- **时区只有两档**（跟随系统 / 固定 UTC+8）。原型第三档「按当日首次活动所在地」要靠定位权限，而这个工具连网都不上。两档已经覆盖真实场景：系统时区一换，「09:00 上班」会变成当地时间 09:00，整条工作日边界平移；固定住等于「按公司那边的钟算」。
- **年终奖没有「仅在发放月计入」**。那一档下时薪一天都不变，没有可算的东西；留着它只会让「为什么时薪没变」变成一个要解释的问题。剩下三档（按月份 / 按金额 / 按年薪 %）都摊进 12 个月，而且**只有它们会改变时薪**。

### 排班、节假日与「今天算不算工作日」

这一块是这一版最大的改动，因为它把「周一到周五」从一个常量变成了配置。

- **形态不落盘**：`WorkForm`（双休 / 大小周 / 单休 / 自定义）是由「七天格子 + 大小周奇偶」反推出来的。存一份 form 就会跟 `days` 打架——用户改了单天，form 还写着「双休」。
- **大小周不能存「本周六上不上」**。那是个第二天就失效的布尔。存的是**奇偶性**：从 1970-01-05（周一）起的周序号 `% 2`，等于它就上班。判定用 `num_days_from_ce()`，不能用 `weekday().num_days_from_monday()`——后者除以 7 恒得 0，会让大小周退化成「每个周六都上班」。这个 bug 真出现过，`alternating_saturday_flips_week_by_week` 这个测试就是钉它的。
- **判定顺序是「补班 > 放假 > 周模板」**。补班压过放假、放假压过周末格子：国务院公告里同一天不会既是放假又是补班，但用户手改的表里会，所以顺序必须写死。
- **两张日期表互斥**：把某天标成放假，它会自动从补班表里删掉，反之亦然。同一天既放假又补班是自相矛盾的配置，不该让用户自己收拾。
- **不自动同步国务院公告**。原型 2186 行写得很清楚：硬编码一年至少算错 3–5 天，用户的日薪会被系统性拉偏。所以这张表由用户维护，工具只负责按它算。
- **日历格子是 Rust 排好的**：哪格是今天、哪天放假、1 号前空几格、下个假日还有几天，全部在 `settings_win::view()` 里算完，前端只管按顺序画。连「点的是哪一天」回传的都是 `YYYY-MM-DD` 字符串，不让前端碰日期。

### 时区：只有一个接缝

`Settings::tz_fixed` 为真时，`clock()` 把「现在几点」换算到 UTC+8；为假时就是 `Local::now()`。两者都返回 `DateTime<FixedOffset>`，**同一个类型**——否则调用方要写两份代码，迟早有一份忘了改。

它只影响墙上时钟，不影响时间戳：`timestamp()` 在任何时区下都是同一个数，所以已经落盘的暂停区间、加班起始点不会因为切时区而重算。

### 弹性排班：整个班次跟着人走

开启之后，今天第一次碰键鼠的时刻就是这一天的上班点。三个关键决定：

- **锚点落盘**（`day_anchor`，Unix 秒），但 `today_anchor()` **只认今天的**。昨天的锚点留在文件里无害，拿它来给今天定价就有害了——今天的班次会从昨天那个时刻开始算，金额一早就多出一截。测试 `yesterdays_anchor_does_not_apply_to_today` 钉这一条。
- **平移量是带符号的差值，不做 `rem_euclid`**。08:00 上班相对 09:00 的配置应该是 −60 分钟；包成 1380 会把整套作息推到第二天，「已工作」直接变成满勤。`Shifted` 里每个时刻各自 `rem_euclid(1440)`，跨零点照样成立。
- **今天还没动过键鼠 = 一分钱都不记**。这条最容易被漏：不平移时 `calendar_shifted(0)` 会退回配置里的 09:00，于是 10:30 才坐下的人看到「09:00 到现在已经赚了 80 块」。所以 `snapshot_at` 里有个显式的 `waiting` 分支，把已计薪秒按 0 处理。

锚点取 `ts − idle`（最后一次输入那一刻），不是 `ts`——用 `ts` 会把「程序启动到你碰鼠标」那几秒也算成工时。`idle ≥ 5 分钟`时干脆不钉：开机自启的机器不该在凌晨三点给自己钉一个上班点，等人回来再说。

### 三套文案：换语气，不换数字

`hud.js` 里的 `COPY` 有三张表（情绪向 / 严谨 / 静默），键必须逐一对齐——少一个键就会掉进 `|| labels.on` 的兜底，而兜底文案冒到静默档里正是这个功能最容易出的丑。

- 情绪向那套逐句抄自原型稿；严谨只陈述事实；静默返回空串。
- 静默不是「清空文字」而是**整行不占位**（`.hud[data-copy="silent"] .hud-tip { display: none }`）：实测窗口高度 222 → 199，留一条 16px 的空白比说话还吵。
- 静默还顺带关掉午休与久坐提醒——主动关心在那一档就是唠叨；下班那条只说数（`¥367.82`），因为那是账。
- **三套共用同一份数字**：同一帧下三档的金额都是 `288.968`，`copy_style_changes_nothing_but_words` 把这个契约钉在 Rust 侧。

### 多显示器：按名字记，不按索引

- 位置存 `win_by_monitor: {"<显示器名>": {x, y}}`，键是**名字**：索引随插拔变（笔记本合盖再开，外接屏就从 1 变 0），按索引记等于每次插拔都把位置记到别人头上。
- `pick_position()` 的顺序是「这块屏的记录 → 兜底那份 `win` → 默认摆放」。单独抽成函数不是为了好看，是因为 `setup()` 里的代码没法测，而这条顺序搞反的表现（插上外接屏，窗口还留在笔记本那块屏上）只有真机看得见。
- 恢复之后一律 `clamp_into_screen`：那块屏被拔掉时坐标可能落在屏幕外，而屏幕外的窗口用户抓不回来——看不见也就拖不动。
- 「固定在主屏」只管启动那一下，不把窗口硬拉回来：跟鼠标抢窗口比不听话更烦人。
- `validate` 会清掉空名字和离谱坐标，并把条目封顶 8 条——纯防坏文件。

### 首启：先填数，再露脸

首启的判定是**「`settings.json` 当时存不存在」**，不是配置里的一个 `first_run` 字段。存字段的话，所有老用户的文件里都没有它，`serde` 的默认值会把每个人都当成新装的——那才是真正的回归。

首启那一次：

1. 设置窗口自动推出来，悬浮窗**继续藏着**。不藏的话，用户先看到的是示例的 8000 块在那儿跳，然后才看到自己的数——那半秒足够让人认定这软件在瞎算。
2. 页顶出现一条引导横幅，光标自动落在月薪输入框上并**全选**（想干的第一件事就是把它替换掉，不该先找地方点一下）。
3. 第一次写盘（`take_fresh()` 从 true 翻成 false 那一刻）悬浮窗才露脸。
4. 用户直接关掉窗口没填：下次启动再来一次。数据没落盘就等于没设置过。

引导条上**没有「跳过」按钮**——跳过之后他看到的还是别人的工资。

### 几个实现上的决定

- **写盘只有一条路径**：设置窗口不自己读写 JSON，它只发补丁；合并、校验、原子写全在 `AppState::mutate → validate → save_to` 那一条线上。两条写路径迟早出现「设置里是 8000、悬浮窗按 9000 算」。
- **补丁是逐字段的 `Option`，不是整份 `Settings`**。前端漏传一个字段，整份结构写回去就会把 `pauses`、`win`、`leave_days` 这些界面上根本不展示的东西清空。
- **高亮回填时跳过正在输入的那个框**。不跳的话，`8000.` 打到一半会被 `8000.00` 冲掉。
- **改作息要先合并再推导**。顺序反了，手工填的「每日计薪工时」会被作息推导覆盖。
- **强调色只作用于中性状态**。午休琥珀、加班蓝、请假紫是语义色——「现在是加班」这件事不该被主题色吃掉。色值只认 `#RRGGBB`，因为它是直接 `style.setProperty("--user-accent", …)` 的。
- **信息密度的标记写「关掉了什么」**（`data-off="m b"`），不是「显示着什么」。写反过一次：四个开关全开时版面一片空白——这种错只有真机截图能看出来。
- **改尺寸当场改窗口宽度**，改穿透当场 `set_ignore_cursor_events`。否则「设置了没反应」和「设置坏了」在用户眼里是同一件事。
- **设置窗口移动不改悬浮窗位置**。`Moved` 事件只认 `label == "hud"`；不拦的话，把设置窗口拖一下，悬浮窗下次启动就跳到那个位置去。

关于「生效时机」：原型 04-H 把作息定为「次日 0 点生效」，这一版是**立即生效**。当天中途换作息会让进度条跳一下，但比「改了没反应」好解释，也比假装次日生效诚实。

调试时想直接拉起设置窗口（只能从托盘开，非交互桌面上点不到）：

```bash
PAYPULSE_SETTINGS=1 app/src-tauri/target/x86_64-pc-windows-gnu/debug/paypulse-app.exe
```

只在 `debug_assertions` 下存在，发布版没有这个钩子。

## 八、通知、快捷键与后台行为

### 通知是自己画的一个窗口

系统通知要走 `tauri-plugin-notification`，而它在 Windows 上牵进来的是一整套 WinRT 绑定——为了弹两行字多一个插件、多一堆编译时间，换来的好处只有「能进通知中心」这一条。所以这里是 `toast.html` 自己画。

代价写在这儿：**它不进 Windows 通知中心**，错过就没了，也不受「专注助手」管理。所以它只用来报「今天到账多少」这种看一眼就够、不需要回看的信息。真正的待办类提醒不该走这条路。

三条硬约束：

- **不抢焦点**：建窗口时 `focused(false)`。用户正在打字，弹个通知把光标抢走是最招人烦的。
- **不叠、不排队**：后一条直接覆盖前一条。连弹三条只会让人把通知关掉。
- **5 秒自己收**，点一下提前关。

两处不显然的实现：

- `GENERATION: AtomicU64` 记「这是第几条」。5 秒前那条的定时器在关窗口之前先认一下编号还是不是自己那一代——不判这个，刚弹出来的新通知会被上一轮的定时器一起关掉。
- 窗口**懒创建**：绝大多数会话只弹一两次，为它常驻一个 WebView 是几十兆的浪费。但创建必须在主线程（`run_on_main_thread`）——`tick` 是命令，跑在工作线程里。

位置固定在**主**显示器右下角（留 56pt 给任务栏），不跟鼠标所在屏：通知要出现在一个可预期的地方，跟着鼠标满屏跑反而找不到。

### 三种提醒，各自只报一次

| 提醒 | 触发 | 为什么这样触发 |
|---|---|---|
| 下班 | `state` 从非 `done` 变成 `done` 的那一帧 | 用「金额满日薪」判，加班结束时会再弹一条。要的是边沿，不是状态 |
| 午休 | `lunch_in_sec <= 提前分钟` | 区间不是边沿（会连着几十帧都成立），所以靠 `lunch_fired` 挡 |
| 久坐 | 连续在岗满 `sit_min` 分钟 | 状态一变就清零——离开工位回来该重新计，不是接着累计 |

第一帧**一条都不发**（`seeded`）：不这样的话，下午六点之后第一次启动会立刻弹「今日已到账」——那不是提醒，那是把历史当成刚刚发生的事。

免打扰区间跨零点要摊平：`dnd_from > dnd_to` 时判据是「≥ from **或** < to」，不是「在两者之间」。而两端相等当**关闭**处理——不然「0 点到 0 点」会把全天静音，用户还以为自己什么都没设。

### 空闲检测：起点是「最后一次碰键鼠」

暂停区间的起点用 `ts − idle`，不是「发现它空闲的那一刻」。用后者的话，用户离开 5 分钟回来，会发现那 5 分钟照样计薪——这个功能就等于没有。

恢复判据是「空闲 < 5 秒」而不是「idle 归零的那一瞬」：`GetLastInputInfo` 的粒度是一秒，刚回来那一下读数还没变，抓不住边沿。

`GetTickCount` 49.7 天回绕一次，差值用 `wrapping_sub` 算，回绕时相减仍然正确。这是这个 API 唯一不显然的地方。

用户自己点了暂停，空闲检测就不再管那一段（`idle_open` 清掉）——否则「回来」时会去恢复一个不是它关的暂停。

### 快捷键：录制、拒绝裸键、20ms 泵

存的是字符串（`"Ctrl+Shift+P"`），不是 VK 码：配置文件要能看懂，也要能被人手改。

- **裸键一律拒绝**（`parse("F5")` → `None`）。没有修饰键的全局快捷键会抢走整个系统的那个键。设置页也拦了：只按修饰键不提交、没有修饰键直接提示、Esc 取消录制。
- **四个键各自独立**（显隐 `P` / 穿透 `L` / 计时 `Enter` / 额外收入 `E`）：`parse` 认不出来只跳过这一个，另外三个照常注册。手滑写成 `Ctrl+Shift+` 不该让四个全废。
- **注册失败只记一条日志**：`Ctrl+Shift+字母` 是输入法和录屏软件最爱的组合，被占了很常见。那一个失效，不该让悬浮窗起不来。
- **专用线程 + 自己泵消息**：`RegisterHotKey(null, …)` 绑的是调用它的那个线程，`WM_HOTKEY` 也只投到那个线程的队列；主线程的消息循环是 tauri 的私有实现，踩不进去。20ms 一轮 `PeekMessage` 而不是阻塞在 `GetMessage` 上——阻塞了就收不到「绑定变了」这个新指令。

### 记一笔：唯一一处与时间无关的钱

`Ctrl+Shift+E` 弹一张 340×196 的小卡，填金额、回车、走开。它记的东西存在 `extras: [{date, amount}]` 里，是这个程序里**唯一**不以 `f(now)` 形式存在的金额。

**它只加在「本月已到账」那一行。** 加进 `amount_milli`（今天的已赚）看着也顺，但那样一笔报销会变成「今天赚的」：进度条冲到 100%，而日薪除出来的时薪没变，两个数字当场互相打脸。测试 `extra_income_lifts_month_total_but_not_the_rate` 就是拦这个的——顺带钉住「12 月那笔不该在 11 月被看见」。

**换算在 Rust 里做，外壳不做乘法。** JS 的 `12.34 * 10000` 是 `123399.99999999999`，四舍五入后少一毫；单笔看不出来，一个月几十笔就是漂移。所以输入框把**字符串**原样交给 `parse_yuan`，它按小数点拆成两段整数再拼：`12.5` → `12` + `5000`。顺带认 `1,200` 和 `¥88.50`，超过四位小数直接判错而不是四舍五入。

**这扇窗原型稿里没有**，是按「快捷键要真能追加」补的——原型只有那一行说明文字。所以它只做一件事：收金额。没有备注、没有分类、没有列表可翻；记错了去「清除今天 / 本月」，那边连账本一起清（只清计时不清进账的话，用户会看见钱还在）。

三个细节值得记：

- 日期存 `YYYY-MM-DD` 字符串，不存时间戳。按本地日历归月，同一个时间戳在东八区和 UTC 差一天，那笔钱会跑到上个月去。
- 点到别处就 `hide()`，不是 `destroy()`——下次按快捷键是同一个窗口，省一次 WebView 创建。代价是页面还活着，所以每次显示前要清空输入框，否则留着上一笔的钱。
- 文件里的坏数据逐条丢，不整份丢：`2026-13-45` 那种日期永远落不进任何一月，留着只会让「记了但没算」变成一个要查的问题。

### 开机自启只写一个值

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `PayPulse`，路径带引号（不带的话 `C:\Program Files\...` 会被按空格切开当参数）。不碰计划任务、不碰启动文件夹、不写服务——设置页那句「只写入启动项这一个位置」是靠这个决定兑现的，删掉这个值就是干净的卸载。关的时候「本来就不存在」也算成功：目的达到了。

### 关窗口与静默启动

`CloseAction` 两档：最小化到托盘（默认）/ 直接退出。悬浮窗没有标题栏，但 Alt+F4 照样能关它，所以这个分支必须拦在 `CloseRequested` 里。

静默启动只吃掉**第一次**露脸请求。之后从托盘或快捷键叫出来，`ready` 再来就该显示。

### 边缘吸附

- 阈值 8–40pt，`0` = 关。用**物理**像素算：`outer_position` 和 `monitor` 都是物理的，混进逻辑像素在 125% 缩放下会差出小半屏。
- `SNAPPING` 布尔挡住那个死循环：吸附改位置 → 触发 `Moved` → 又算一次吸附 → 位置又被改……看起来像窗口在抽搐。
- 吸附排在「记位置」**之后**：反了的话记下来的是吸附前那个点，下次启动差几像素。

## 九、许可证

外壳 AGPL-3.0（见 `LICENSE`）。计薪引擎为私有仓，只发行二进制。

选 AGPL 而不是 MIT 的原因很直接：这是个桌面应用，别人 fork 之后加上「会员解锁加班统计」再闭源分发是可能的，AGPL 至少要求他把改动放出来。你要是想 fork 自用、改配色、改成自己的薪资，随便改，不用问我。

### 9.1 第三方组件（`THIRD-PARTY.md`）

`THIRD-PARTY.md` 列出真正链接进 `paypulse-app.exe` 的 **227 个 crate** 及各自许可，由脚本生成，不要手改：

```bash
export PATH="$HOME/.cargo/bin:$PATH"
python app/tools/license-scan/scan.py
```

三件事值得说清楚：

**为什么统计口径是 `cargo tree --target` 而不是 `Cargo.lock`。** 后者是整个工作区的解析结果，含 macOS / Linux / wasm 分支，直接列会虚报几十个根本没进这个 exe 的包。再叠 `--edges normal,build` 去掉 dev-dependencies——测试用的不进产物，也就不产生分发义务。

**结论是全宽松，零 GPL。** MIT 197、Apache-2.0 155、Unicode-3.0 19、Unlicense 7、BSD-3-Clause 6、Zlib 6、MPL-2.0 5、0BSD/CC0-1.0/MIT-0 各 1（双许可在每个分支各计一次，所以合计大于包数）。唯一带 copyleft 的是 MPL-2.0 那 5 个（`cssparser` / `selectors` / `dtoa-short` / `option-ext`），它按**文件**生效，这几个 crate 一行没改，义务就只有「告知 + 可获取源码」——表里每行 crate 名都链到 crates.io 对应版本，那就是源码入口。

**所以它必须进安装包，不能只在仓库里。** MIT / Apache-2.0 的义务是随**二进制分发**触发的，对象是「拿到安装包的人」，而仓库里的文件他们收不到。`bundle.resources` 把这份清单复制到安装目录根，装完就能看到。`licenseFile` 那栏另指 `../LICENSE`（AGPL 全文），供安装向导显示。

生成脚本自己也踩过一个坑，记在这儿免得下次重犯：`cargo tree --prefix none` 对 proc-macro crate 也会打括号——`serde_derive v1.0.229 (proc-macro)`——只判「括号非空」会把 19 个过程宏当成自家 crate 归到「本项目」里，少声明一大块。路径依赖的特征是括号里含 `/` 或 `\`。

## 十、上线前手点清单

130 个测试证明的是「算得对」，不是「看得对」。下面六项机器判不了：要么需要真鼠标，要么需要真实的光标位置、真实的系统通知区域、真实的零点。每项给三件事——怎么造条件、该看到什么、不对该查哪儿。

### 10.1 主题四档

设置 → 外观，四档「深色 / 纯黑 / 浅色 / 跟随系统」（默认深色）。

**该看到**：数字、副行、分隔线在每一档都清楚，没有白底白字或黑底黑字；切到「跟随系统」后改 Windows 的 `设置 → 个性化 → 颜色 → 选择模式`，应用**不用重启**就跟着变。

**不对查这里**：档位选完退出再进来又变回去了 → 是序列化问题，看 `%APPDATA%\com.bydota.paypulse\settings.json` 里 `theme` 写成什么（合法值是 `dark` / `black` / `light` / `system`，写错会静默落回 `dark`）。

### 10.2 夜班态（跨零点）

排班设上班 `22:00`、下班 `02:00`，等到真实 `00:30` 左右看一眼；不想等就把系统时间往前拨（会影响其他程序，建议在虚拟机里做）。

**该看到**：进度条按「班次进行到一半」走，而不是归零或冲满；剩余时间显示约 `1 小时 30 分`；金额是在累加的正数。

**金额写着「在岗」却一动不动**：先看日志最后几行（`%APPDATA%\com.bydota.paypulse\paypulse.log`）。出现 `空闲 320s（…暂停中=true，这段是空闲开的=true）` 说明空闲检测判定人走了——键鼠停够 `idle_min` 分钟就会这样，动一下鼠标即恢复，这是设计；出现 `收掉 N 段没收口的暂停` 说明上个进程没正常退出，残留的暂停已经清掉，金额从那一刻起会继续涨。真机上如果这两行都没有、钱还是不动，才是算式的问题。

**不对查这里**：下班时间早于上班时间时，引擎按「次日」解释 —— 这条在时钟库测试里是覆盖的（`night_shift_counts_across_midnight`、`night_shift_belongs_to_the_day_it_started`），真机若不对，问题多半在系统时钟或时区接缝，不在算式。

### 10.3 通知弹窗

三种提醒：午休开始前（默认提前量，见设置）、久坐（默认连续 60 分钟）、下班。等不到就把久坐间隔临时调到 15 分钟（下限），然后照常干活；下班那条最快的造法是**把下班时间改成「现在 + 1 分钟」**。

**该看到**：从屏幕右下角滑入，停几秒后自己滑走；点一下能关掉。文案风格选「静默」时，**午休和久坐两条都不再出现，但「今日已到账」那条照发**——那条是账，不是唠叨，只把正文压成一个金额。

**下班通知的触发点是「班次到点」，不是「日工时攒满」**。这两件事在正常排班里恰好同时发生（9 小时班 − 1.5 小时午休 = 7.5 小时日工时），但把下班改成「一分钟后」时就分家了：班次只剩一分钟，日工时还是七个半小时，永远攒不满。早先按「攒满」挂通知，于是到点了什么都不发生——用户看到的是「计时卡在最后一秒、钱不涨、通知也不来」。现在两条判据取或，日志里会留一行 `通知已弹：今日已到账 / ¥…`。

**不对查这里**：弹窗出现在屏幕中间或左上角 → 是显示器坐标换算（`win_by_monitor` 按显示器名取位置，不是索引），先看是不是多屏、主屏是不是第二次启动后被改过。窗口建出来却是空白 → 通知窗的页面还没挂上监听，看日志有没有 `通知已弹出`；没有就是事件没到，有就是页面没画，两回事。两条提醒挨得近时若叠成两层窗口，说明还缺一个 Toast 队列，记下来别当成 bug 追。

### 10.4 快捷键

默认四组，顺序与原型稿一致：显示/隐藏 `Ctrl+Shift+P`、鼠标穿透 `Ctrl+Shift+L`、开始/结束计时 `Ctrl+Shift+Enter`、记录额外收入 `Ctrl+Shift+E`。

**该看到**：在**别的程序**（记事本、浏览器）聚焦时按下也生效；`P` 连按两次是「收起 / 展开」而不是无反应；`L` 按下后窗口上的按钮点不动了、点击穿到下面那层（再按一次恢复）；`E` 弹出一张只有金额的卡片，填 `300` 回车 → 绿字「已记 ¥300.00」，再按 Esc 走开；设置页录制新快捷键时，只按一个字母应该被拒（不允许裸键）。

**这一项只能人工按，机器代验不了。** 合成按键（`keybd_event` / `SendInput`）在本机测过：连一个只做「自己注册 `Ctrl+Alt+F9` + `PeekMessageW` 收 `WM_HOTKEY`」的独立小程序都收不到消息，说明注入的键进不了系统热键那条路。所以「AI 说快捷键好了」这句话永远只能是推测，只能人按。

能机器验的部分是**消息进来之后**：向热键线程 `PostThreadMessageW(tid, WM_HOTKEY, id, 0)`（tid 在启动日志里），窗口会真的藏起来、再按真的回来，日志各留一行 `快捷键触发 id=N`。所以「收不到键」和「收到键但没干活」这两件事可以分开判。

**按了没反应，按这个顺序查**（第一条 90% 的情况都是它）：

1. **程序在不在跑**。任务管理器里没有 `paypulse-app.exe`，按什么都不可能有反应——托盘图标也跟着没了。`Ctrl+Shift+P` 只是「显隐」，不是「启动」。
2. **这个组合现在到底绑的是哪个**。默认显隐是 `Ctrl+Shift+P`（原型稿 1378 行），但设置页可以录成别的，比如 `Ctrl+Shift+K`。看 `settings.json` 里的 `hotkey.show`，或直接看日志启动那几行 `快捷键 Ctrl+Shift+K（id 1）注册成功`——注册的是哪一个，就只有那一个灵。
3. **组合是不是被别的程序占了**。占不到就注册失败，这时会**直接弹一条通知条**「这个快捷键没抢到」（原型稿 2790 行要求「不能静默失败」），日志里同时有一行 `注册失败` 带系统错误码。输入法、录屏、截图工具都爱占 `Ctrl+Shift+字母`。
4. **焦点在提权窗口上**。UAC 提示、任务管理器（以管理员身份）这类高完整性级别的窗口在前台时，普通进程的热键收不到。

**已经验过的链路**：`Ctrl+Shift+K` 按下 → 日志两行 `快捷键触发 id=1` → 悬浮窗 `vis=1 → 0 → 1`。这条是真机真键按出来的。

**不对查这里**：`Ctrl+Shift+P` 与 VS Code 的命令面板同键，同时开着两个，谁先注册谁得到（后注册的那个会收到上面的冲突提示）。

**`Ctrl+Shift+E` 记完去哪看**：展开档那句「本月已到账」会涨这一笔，日薪、时薪、进度条都不动——这是刻意的，见下一节。记错了用「数据与隐私 → 清除今天 / 本月」把那笔一起清掉（清除会连账本一起清，不只清计时）。

### 10.5 开机自启

设置 → 启动 → 打开「开机自启」，然后看注册表：

```
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v PayPulse
```

**该看到**：值名 `PayPulse`，数据是带引号的完整 exe 路径（`"C:\...\paypulse-app.exe"`）。只此一处，不写计划任务、不写启动文件夹、不写服务。关掉开关后该值消失。

**不对查这里**：路径没引号 → 装到含空格的目录下会被 Windows 按空格切成参数，起不来。安装模式是 `currentUser`，所以自启写 HKCU 是对的；写成 HKLM 会在标准用户下静默失败。

### 10.5 右键菜单

在悬浮窗上按右键，弹的是**我们自己画的一扇深色小窗**（不是系统原生菜单）：设置… / 切换尺寸 / 暂停计时 / ─── / 今日明细 / ─── / 退出，五项按原型 01-D 画成深色玻璃，跟悬浮窗同一套视觉。系统原生菜单在 Windows 上永远是浅色灰底，跟深色悬浮窗不搭，所以换成了自绘窗（`menu.rs` + `menu.html`）。

托盘菜单**保留原生**：托盘是系统通知区的一部分，菜单本来该跟着系统走，浅色反而和「开始菜单 / 其它托盘图标」一致。

**该看到**：深色菜单出现在鼠标位置，点哪项就做哪件事；「暂停计时」前面有勾（暂停中就勾上）；「切换尺寸」右侧标注当前档位名。

**不对查这里**：

- 弹出的是网页菜单（重新加载 / 另存为 / 检查 / 打印）→ 前端那条 `contextmenu` 的 `preventDefault` 没跑到，或者 `hud_menu` 命令没注册。WebView2 的默认菜单是 DOM 默认动作的后果，拦掉事件它就不弹。
- 菜单刚弹就缩回去 → 这扇窗靠「失焦即收」（`Focused(false) → hide`）兜底，如果 `open` 里主动 `set_focus`，抢焦点会立刻触发失焦回调。所以菜单窗**不 `set_focus`**，让用户点击时 Windows 自然给焦点。
- 右键出来一块空白窗 → 懒创建的透明窗口第一次 `show()` 是空白的（WebView2 没渲染首帧）。菜单窗在启动时就 `prewarm` 建好（`visible(false)`），右键时只 `show()`。
- 菜单跑到另一块屏上 / 位置偏 → 鼠标坐标不能从前端 `contextmenu` 的 `screenX/screenY` 传（那是 CSS 逻辑像素，混合 DPI 多屏会偏）。改由 Rust 侧 `GetCursorPos` 拿物理坐标、`PhysicalPosition` 落位。

### 10.5.1 今日明细

原型第 1379 行列的第五项「今日明细」，原型只写了一行字、没画过这扇窗的样子。为不凭空自创，界面按悬浮窗同一套深色玻璃语言做的（`detail.rs` + `detail.html`，360×460）：今日已赚、白干价值、午休加班段（每段单独算白干价值）、暂停段、额外进账、当前状态，底部一个导出。所有数字都由 `detail_view` 命令在 Rust 侧算好，前端一行算术都没有。

同样靠 `prewarm` 预热 + 失焦即收；但它是「看一眼就走」的窗，打开时可以 `set_focus`（不像菜单窗要避免抢焦点）。

### 10.6 边缘吸附

把窗口往屏幕四边拖，慢慢靠近边缘（默认阈值 24pt，设置里 `0`–`40` 可调，拖到 `0` 即关闭）。

**该看到**：进入阈值内「吸」到贴边；**拖过头、只剩一条缝露在桌面上时，松手要自己拉回来贴住**；松手后记住位置，下次启动回到同一处。

**吸附发生在「松手 200ms 后」，不是拖动过程中**（原型稿 1375 行）。这条差别的真机表现很具体：之前是每个 `Moved` 就吸，等于用户还按着鼠标、系统正处在自己的拖动循环里的时候，我们从旁边把窗口挪走——两下抢同一个窗口，把它拖到任务栏上时会看到窗口**来回钉在那儿，腾出来的地方留一片残影**。现在位移只敲一下「刚动过」，静默满 200ms 才落一次，拖动全程归系统管。吸附落位之后还会请求重画「新旧两块」的并集（`platform::repaint_rect`），把透明窗口挪走时留下的残影擦掉。

**边界是「工作区」不是「屏幕」**：屏幕 2304×1440、任务栏 48，贴底该停在 `1440−48−窗口高`，而不是 `1440−窗口高`。用屏幕矩形夹的话，窗口下半截落在任务栏后面，用户看到的不是「贴住了」而是「卡了一半」。

**不对查这里**：

- 拖到边上不吸、或者只在「差一点点」时吸 → 判定写成了 `(right − (x+w)).abs() <= th`。**越过边线之后差值是负的，绝对值只会越来越大**，越出去越吸不住。必须是单向的 `right − (x+w) <= th`，负数也成立，越出去多少都能拉回来。这条有四个测试钉着（`snap_axis`）。
- 双屏挪不过去 → 越界判定没放行「那边还有一块屏」。`monitor_at()` 查一下越出去的点，有别的屏就不许拉回。
- 125% / 150% 缩放下吸偏小半屏 → 阈值被当成逻辑像素用了，实际必须用物理像素算。

**真机怎么验（不用鼠标）**：`SetWindowPos` 挪窗口会触发同一个 `WM_MOVE`，走的就是吸附那条路。实测（2880×1800、缩放 1.25、工作区到 1740）：设到 `(2740,300)` → 落在 `(2502,300)`；设到 `(600,1620)` → `(600,1465)`；设到 `(2800,1700)` → `(2502,1465)`（两条轴同时拉回）；设回中间 `(1200,800)` 不动。

「松手才吸」这条另有一个连拖测试（`tmp/snap_debounce_test.py`）：14 次连续位移一路拖到 `y=1740`（窗底 2015，深进任务栏 275px），**连拖结束时窗口仍在 1740——没被拽回去**；停手 450ms 后落到 `1465`，底边正好 1740。

### 要不要买代码签名证书

不买也能发，代价是每个下载的人第一次运行会看到 SmartScreen 的「Windows 已保护你的电脑」，得点「更多信息 → 仍要运行」。对方若是同事或熟人，一句话就能带过。

买的话是 OV / EV 代码签名证书，按年订阅、要实名审核，签名后那个蓝屏才消失，且**新证书仍要攒一段时间的下载量**信誉才会彻底不被拦。自签名证书在别人的机器上照样弹窗，等于没解决——别在这上面花时间。

判定很简单：只给自己和熟人用 → 不买；要挂到公开页面给人随便下 → 再买。
